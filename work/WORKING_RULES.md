# 업무 화면 작업 규칙

## 리스트 UX 규칙 — 최신 기준

- 프로젝트 화면은 카드 대신 리스트로 개편합니다. 아래 과거의 프로젝트 2열 카드 규칙보다 이 기준을 우선합니다.
- 오늘 할 일·프로젝트·업무·할 일 등 모든 표 형식 리스트의 헤더는 열 종류와 관계없이 가로 가운데 정렬합니다. 본문의 정렬을 헤더에 그대로 적용하지 않습니다.
- 본문의 프로젝트명·업무명·할 일 제목·설명 등 길어질 수 있는 텍스트는 왼쪽 정렬합니다.
- 본문의 마감일·날짜·시간·진행 상태·개수·완료 비율·체크박스·이동 화살표·집중 및 더보기 아이콘·동작 버튼은 각 열의 가운데에 정렬합니다.
- 헤더 이름과 정렬·필터·드롭다운 아이콘은 하나의 묶음으로 가운데 정렬하고, 묶음 내부도 세로 가운데 정렬합니다. 아이콘 표시 여부나 정렬 방향 변경으로 헤더가 이동하지 않도록 아이콘 공간을 확보합니다.
- 모든 셀의 내용은 세로 가운데 정렬합니다. 긴 이름은 해당 열 안에서 줄바꿈 또는 말줄임 처리하고, 날짜·상태·동작 열을 밀거나 침범하지 않게 합니다.
- 검수 시 전체 헤더의 가운데 정렬, 긴 텍스트 본문의 왼쪽 정렬, 짧은 값·아이콘의 가운데 정렬을 각각 확인합니다. 긴 이름·빈 날짜·필터 적용·좁은 화면에서도 같은 기준을 유지합니다.

## 공통 UX 적용 범위 — 최신 기준

- 오늘 할 일·프로젝트·캘린더의 도구·탭·글자·아이콘은 DESIGN.md의 ‘공통 UX — 2026-10-27 최신 기준’과 common-ux.css를 공유합니다. 아래 과거의 화면 유지 범위보다 이번 공통 정리 범위가 우선합니다.
- 탐색은 텍스트, 오늘 할 일의 보기 전환은 아이콘, 공통 도구는 아이콘, 선택 메뉴는 텍스트와 SVG 화살표를 사용합니다. 같은 기능에 다른 아이콘을 사용하지 않습니다.
- 탭 선택과 스크롤바 유무로 콘텐츠 기준선이 이동하지 않는지 확인합니다. 타이머는 공통 집중 패널과 하단 미니 바만 사용하며 보기 전환·다른 탭에서도 상태를 유지합니다.

## 오늘 할 일 테이블 — 현재 요청 기준 (기존 목록 규칙보다 우선)

- 변경 대상은 오늘 할 일 목록 영역입니다. 다른 탐색·프로젝트·캘린더의 디자인·데이터는 유지합니다.
- 기본 열은 완료 체크 → 프로젝트 → 할 일 → 실제 마감 → 집중입니다. 행 높이 48px, 제목 14px, 프로젝트 13px이며 기존 다크 스타일을 재사용합니다. 실행 시간과 하위 항목은 행에 펼치지 않습니다.
- 완료 상태 탭과 정렬 아이콘, 기존 추가·타임라인 진입점을 유지합니다. 열 제목에서 프로젝트·이름 검색·마감 필터와 정렬을 열며 별도 필터 설명 줄을 만들지 않습니다.
- 제목/행 클릭은 오른쪽 380px 상세 패널, 집중 버튼은 실제 할 일 제목의 타이머 패널입니다. 타이머는 숫자를 눌러 분 단위 수정하며 시작·일시정지·종료는 접근성 이름을 가진 아이콘입니다. 다른 업무에 실행 중인 타이머가 있으면 먼저 종료합니다.
- 하위 할 일은 기존 checks를 사용하여 추가·수정·완료·휴지통 처리를 지원합니다. 메모는 버튼 없는 편집 영역에서 텍스트·이미지를 붙여넣고 선택·삭제합니다. 이미지 첨부는 2MB 이하, 파일 선택창을 열지 않습니다.
- 텍스트는 기존 notes와 검색·내보내기를 유지합니다. 안전한 텍스트/이미지 배열 memoParts와 기준 텍스트 memoText만 선택적으로 추가합니다. HTML을 그대로 저장하거나 실행하지 않습니다. 저장 실패 시 입력을 유지하고 오류를 알립니다.
- 완료·마감·시간 배치·프로젝트 관계·계정별 저장 키는 유지합니다. 가상 계정에서 필터·정렬, 하위 항목 변경, 이미지 붙여넣기/삭제 및 새로고침 보존, 타이머 중복 방지를 검수합니다.


사용자가 보고 싶은 정보를 빠르게 찾고, 필요한 항목을 쉽게 추가하며, 정돈된 화면에서 일을 처리하도록 설계합니다. 앞으로 기능을 추가하거나 화면을 수정할 때 정보 집중도, 조작의 간결함, 정렬과 여백의 일관성을 함께 확인합니다.

이 문서는 이후 작업의 판단 기준입니다. 화면별 현재 동작과 치수는 [DESIGN.md](DESIGN.md)를 따릅니다. 새로운 사용자 요청으로 기준이 바뀌면 해당 규칙도 함께 갱신합니다. 변경 이력의 오래된 표현을 최신 기준보다 우선하지 않습니다.

## 보고 싶은 정보에 집중하기

화면을 구성하기 전에 사용자가 여기서 확인하거나 처리하려는 일을 한 문장으로 정합니다. 예를 들어 “오늘 실행할 일을 순서대로 확인한다”, “특정 프로젝트의 미완료 업무를 찾는다”, “이번 달의 일정과 실제 마감을 확인한다”처럼 구체적으로 작성합니다. 화면의 정보와 동작은 이 목적에 맞춰 선택합니다.

| 수단 | 사용자에게 제공할 역할 | 작업할 때 지킬 기준 |
|---|---|---|
| 기준 날짜 | 어느 날의 계획을 보는지 확인 | 선택한 날짜를 알아볼 수 있고 이전·다음·오늘로 쉽게 이동 |
| 목록·타임라인·주간·월간 | 목록의 실행 순서, 시간 배치, 주간·월간 흐름 확인 | 보기 전환과 날짜 변경이 실제 계획·마감을 임의로 바꾸지 않음 |
| 프로젝트·업무·할 일 화면 | 확인할 정보의 단위 선택 | 현재 단위를 구분하고 연결된 상세로 자연스럽게 이동 |
| 검색 | 이름이나 단어로 필요한 항목 찾기 | 전체·프로젝트·업무·할 일 범위를 구분하고 클릭하면 바로 입력 |
| 필터 | 프로젝트·업무·완료 상태 등으로 결과 좁히기 | 적용 여부와 선택 조건을 확인하고 쉽게 해제·초기화 |
| 접기 | 당장 보지 않을 보조 영역 정리 | 원본 데이터와 일정 의미를 바꾸지 않고 다시 펼칠 수 있음 |
| 상세보기 | 선택한 항목의 관계·날짜·인원·메모 확인과 수정 | 목록의 모든 속성을 반복해서 표시할 필요 없이 해당 항목에 집중 |

- 오늘 실행 목록은 프로젝트 > 업무, 제목, 실제 마감만 기본 표시합니다. 등록된 확인사항·메모는 상세보기에서 확인하며 프로젝트 화면의 기존 확인사항 접근은 유지합니다. 태그·인원은 상세 추가 설정에 둡니다.
- 프로젝트 목록은 프로젝트명·진행 상태·남은 할 일·다음 마감의 리스트로 표시하며 오늘·프로젝트·캘린더의 콘텐츠 폭과 좌우 여백을 통일합니다.
- 프로젝트 리스트는 콘텐츠 영역 안에서 스크롤하고 상단 탐색·도구는 고정합니다. 상세에서 돌아온 목록의 스크롤 위치를 유지합니다.
- 같은 정보는 한 위치에서 이해할 수 있게 합니다. 완료 수가 제목에 있으면 별도 완료율 항목을 반복하지 않습니다.
- 빈 확인사항 입력란과 내용 없는 보조 구역은 공간을 차지하지 않습니다. 첫 항목을 만들 수 있는 진입점은 남깁니다.
- 필터 결과가 없으면 데이터가 없는 상태와 조건에 맞는 항목이 없는 상태를 구분합니다. 조건을 바로 해제할 수 있게 합니다.
- 검색 결과나 필터 때문에 항목이 사라졌을 때 완료·삭제된 것으로 오해하지 않게 합니다. 화면 전환 후에도 적용 범위와 조건을 파악할 수 있게 합니다.
- 필터 선택 후에는 메뉴를 유지하며 결과와 선택 표시를 갱신합니다. 사용자가 반복해서 메뉴를 열 필요가 없어야 합니다.
- 편집 후 돌아오면 가능한 한 이전 보기·조건·스크롤 위치를 유지합니다. 자동 갱신이 사용자의 입력이나 포커스를 빼앗지 않아야 합니다.
- 정보를 접는 기준은 화면 목적에 맞춥니다. 오늘 화면의 지난 시간·보조 목록은 접고 현재 할 일에 집중합니다. 확인사항은 상세에서 전체 표시하고 주간 일정도 전체 표시합니다. 월간 일정은 3행과 날짜 줄의 더보기로 밀도를 조절합니다.

- 리마인드는 실제 오늘 첫 접속에 한 번만 자동으로 엽니다. 이후에는 알림벨로 조회하며 조회 날짜·검색·필터로 미확인 알림을 숨기지 않습니다. 편집 중에는 자동 팝업을 미루고 창 닫기와 개별 확인을 구분합니다.

## 쉽게 추가하고 바로 수정하기

- 빠른 추가는 이름 입력만으로 시작할 수 있게 합니다. 관계·날짜·인원·태그 등 선택 속성 때문에 기본 등록을 막지 않습니다.
- 추가 버튼은 내용과 가까이 둡니다. 목록 아래, 해당 확인사항 영역, 달력 날짜 아래 또는 마지막 일정 바로 아래처럼 결과가 생길 위치에서 추가합니다.
- 화면 하단의 먼 위치까지 내려가야 추가할 수 있는 구조를 만들지 않습니다.
- 오늘 빠른 추가는 목록 상단 +로 제목 입력을 열고 프로젝트·업무 묶음은 해당 구역 ＋를 누르면 제목 추가란을 엽니다. 그 외 기본 화면에는 빈 입력창을 나열하지 않습니다. 호버 또는 키보드 포커스에서 추가 버튼을 보여주고, 클릭하면 해당 항목의 입력창을 엽니다. 터치에서는 호버 없이 접근할 수 있어야 합니다.
- 날짜나 부모 항목이 명확한 위치에서 추가할 때는 그 맥락을 이어받습니다. 검색어·필터만 보고 사용자가 정하지 않은 관계를 임의로 부여하지 않습니다.
- 필터가 켜진 상태에서 추가된 항목이 숨겨질 수 있다면, 추가 결과와 확인할 방법을 사용자가 알 수 있게 합니다.
- 빠른 추가와 확인사항은 ‘저장·취소’를 사용합니다. Enter로 저장하고 Esc로 취소하며, 한글 조합 중 Enter는 저장으로 처리하지 않습니다. 빈 항목과 중복 제출을 방지합니다.
- 텍스트·날짜·관계는 해당 위치에서 편집합니다. 속성을 고르기 위해 별도 팝업을 연달아 여는 흐름을 만들지 않습니다.
- 관계는 값 아래 드롭다운, 날짜는 한 번 클릭해 여는 달력, 상태·진행 단계는 라디오 버튼, 인원·태그는 칩 방식으로 일관되게 제공합니다.
- 선택지를 새로 만들고 연결하는 과정도 같은 흐름에서 마칠 수 있게 합니다. 같은 기능이 화면마다 다른 조작법을 요구하지 않아야 합니다.
- 자동 저장 속성과 명시적으로 저장하는 폼의 동작을 구분합니다. 자동 저장은 정상 상태 안내를 반복하지 않고, 실패 시에는 입력을 보존하며 알려줍니다.
- 취소·바깥 클릭·닫기의 결과를 일관되게 합니다. 취소한 초안을 저장하거나 완료한 입력을 화면 갱신으로 잃지 않아야 합니다.

## 정렬과 여백을 유지하기

여백은 글을 읽고 항목을 구분하는 데 사용합니다. 같은 역할의 요소는 같은 기준선·간격·크기를 공유하며, 개별 항목을 맞추기 위한 임의의 위치 보정을 늘리지 않습니다.

| 대상 | 정렬 기준 | 여백과 크기 기준 |
|---|---|---|
| 메인 작업 영역 | 상단 조작부와 콘텐츠의 좌우 기준선 공유 | 내용이 적어도 화면 하단까지 채움. 긴 목록은 정상적으로 스크롤 |
| 할 일 카드 | 체크박스·제목·마감·추가 버튼의 열을 통일 | 같은 카드의 패딩과 간격을 공유. 추가 내용만큼 자연스럽게 높이 증가 |
| 확인사항 | 할 일 제목의 왼쪽 시작선에 맞춤 | 마감 열을 침범하지 않고 입력 내용이 잘리지 않음 |
| 상세 속성 | 라벨 열과 값 열을 공유 | 프로젝트·업무·상태·날짜·인원·메모·확인사항이 같은 규칙 사용 |
| 상세 편집 | PC 오른쪽 패널, 모바일 전체 화면 | 공통 헤더와 겹치지 않고 내용이 많을 때 내부 스크롤 |
| 리마인드 | 상단 알림벨 아래 팝오버, 행별 제목·동작 기준선 통일 | 내용 높이에 맞추고 화면 경계 안에서 세로 스크롤 |
| 달력 일정 | 같은 행의 높이와 시작 위치를 통일 | 얇은 연결 막대 사용. 기간은 날짜 셀을 가로질러 이어짐 |
| 드롭다운·달력·입력창 | 조작한 요소 가까이에 배치 | 화면 경계에 맞춰 위치·폭을 조정하고 필요한 경우 내부 스크롤 |

- 치수는 DESIGN.md의 현재 기준을 재사용합니다. 예를 들어 목록 카드 간격 10px과 알림 행 안쪽 여백 14px은 역할별 기준이며, 화면마다 별도 값을 만들지 않습니다.
- 글자 크기·행간·색·아이콘 크기·버튼 크기·모서리·간격은 공통 스타일이나 토큰으로 관리합니다. 새로운 값이 필요하면 적용할 역할과 이유를 정하고 같은 역할에 함께 적용합니다.
- CSS의 뒤쪽에 같은 선택자 덮어쓰기를 반복하기 전에 현재 적용 규칙과 영향 범위를 확인합니다. 한 화면 수정으로 다른 보기의 정렬을 깨뜨리지 않습니다.
- 카드의 제목·본문·보조 정보에 위계를 둡니다. 모든 글자를 굵게 하거나 모든 상태에 배지를 붙이지 않습니다.
- 긴 제목은 줄바꿈 또는 말줄임 기준을 정하고 전체 내용을 확인할 방법을 제공합니다. 글자 크기를 계속 줄여 레이아웃에 억지로 맞추지 않습니다.
- 확인사항이나 인원이 늘면 내용 영역이 자연스럽게 늘어나야 합니다. 고정 높이 때문에 글자·입력창·버튼이 잘리는 것은 완료로 보지 않습니다.
- 호버 버튼은 나타나도 주변 제목·날짜가 밀리지 않게 합니다. 기본 상태의 빈 입력 공간은 제거하고 필요한 클릭 영역은 확보합니다.
- 데스크톱의 고정 폭을 작은 화면에 그대로 강제하지 않습니다. 좁은 화면에서는 열·줄바꿈·패딩을 조정해 의미와 조작을 유지합니다.

## 조작 상태와 문구를 이해하기 쉽게 만들기

- 버튼에는 짧고 일관된 동사를 사용합니다. ‘저장’, ‘취소’, ‘오늘’처럼 목적이 분명하면 중복 설명을 붙이지 않습니다.
- 아이콘만 사용하는 버튼에는 접근 가능한 이름을 제공합니다. 작은 아이콘의 보이는 크기와 실제 누를 수 있는 영역을 구분합니다.
- 색은 선택·현재 위치·지연 등 의미를 구별하는 데 사용합니다. 장식용 강조색과 불필요한 테두리를 추가하지 않습니다.
- 텍스트 입력에 민트색 테두리를 다시 넣지 않습니다. 키보드 포커스는 중립색 표시 등으로 구별할 수 있게 유지합니다.
- 완료·지난 시간 등 보조 상태를 흐리게 하더라도 읽을 수 있어야 합니다. 색만으로 상태를 전달하지 않고 체크·라벨·형태도 함께 사용합니다.
- 흐리게 보이는 상태와 실제 조작 불가는 구분합니다. 지난 시간 블록은 선택할 수 있고 선택되면 그 범위를 분명하게 보여줍니다.
- 접기·연결 해제·날짜 비우기·원본 삭제는 결과가 다릅니다. 리마인드의 X와 인원 칩의 X가 원본 삭제로 이어지지 않아야 합니다.
- 드래그한 직후 클릭이 발생해 상세를 열거나 항목을 제거하지 않게 합니다. 드래그 기능에는 키보드 또는 메뉴 방식의 이동도 제공합니다.

## 일정과 데이터의 의미 지키기

- 프로젝트 → 업무 → 할 일의 관계와 확인사항을 구분합니다. 단순한 화면 정리로 원본이나 관계를 변경하지 않습니다.
- 작업 기간, 오늘 실행할 계획, 실제 마감, 시간 배치, 리마인드는 서로 다른 정보입니다. 한 값을 바꾸면서 다른 값을 조용히 바꾸지 않습니다.
- 리마인드는 사용자가 직접 설정한 경우에만 알립니다. 예정일 경과·마감 도래를 리마인드 설정으로 간주하지 않습니다. 알림은 할 일의 보조 정보이며 별도 목록으로 항목을 이동시키지 않습니다.
- 예정일이 지난 미완료 할 일은 오늘 목록에 계속 표시하되 원래 작업 기간·마감은 유지합니다. 미래로 재예약한 일은 앞당기지 않으며 실제 마감이 지난 경우에만 지연으로 분류합니다.
- 지연 여부는 실제 마감 기준입니다. 오늘 계획이 지났어도 실제 마감이 남아 있으면 지연으로 표시하지 않습니다.
- 지연된 일정을 오늘로 옮겨도 실제 마감과 지연 표시는 유지합니다. 두 목록에 중복해서 나타나지 않아야 합니다.
- 자동 정렬은 시간 지정 항목의 시간순을 우선하고 나머지는 마감순입니다. 직접 드래그하면 해당 날짜만 수동 정렬로 바뀌며 자동 정렬로 돌아갈 수 있어야 합니다.
- 시간 배치가 실제 마감을 넘으면 알려주고 사용자의 계획과 마감은 그대로 유지합니다.
- 완료 체크박스와 완료 상태, 업무의 ‘할 일 완료 수/전체 수’는 서로 일치해야 합니다.
- 기존 사용자 데이터·관계·사용자 정의 상태를 보존합니다. 검증을 위해 운영 데이터를 샘플로 덮어쓰거나 초기화하지 않습니다.

## 작업 과정과 완료 기준

1. 변경할 화면의 목적과 사용자 행동을 먼저 정하고, 최신 요청·WORKING_RULES.md·DESIGN.md를 확인합니다.
2. 무엇을 기본 표시하고 무엇을 상세·호버·접기로 옮길지 정합니다. 필요한 정보의 접근 경로도 함께 유지합니다.
3. 기존 컴포넌트와 간격 기준을 적용하고, 영향을 받는 목록·상세·달력 등 연결 화면을 확인합니다.
4. 변경과 관련된 상태를 실제 화면에서 검증합니다. 외형만 수정했다면 시각 확인을 우선하고, 날짜·정렬·저장 등 동작을 바꿨다면 의미 있는 동작 검사도 수행합니다.
5. 결과와 남은 제한을 알리고, 동작이나 디자인 기준이 바뀌었으면 관련 문서를 함께 갱신합니다.

다음 항목은 변경된 화면에 해당하는 범위에서 확인합니다. 관련 없는 화면을 매번 전부 검사할 필요는 없습니다.

- [ ] 사용자가 현재 날짜·보기·검색 범위·필터를 이해하고 원하는 정보로 좁힐 수 있다.
- [ ] 주 정보가 먼저 읽히며 중복 제목·빈 보조 영역·불필요한 안내가 없다.
- [ ] 빈 상태에서도 첫 항목을 추가할 수 있고, 등록 위치와 결과가 예측 가능하다.
- [ ] 호버·포커스·터치로 추가 기능에 접근하고 저장·취소를 마칠 수 있다.
- [ ] 인접 카드의 체크박스·제목·마감과 상세의 라벨·값 기준선이 일치한다.
- [ ] 같은 역할의 패딩·행간·카드 간격·아이콘 크기가 일치한다.
- [ ] 긴 제목·여러 확인사항·많은 인원·빈 값에서도 겹침이나 잘림이 없다.
- [ ] 큰 화면과 좁은 화면에서 입력창·드롭다운·팝업이 화면 밖으로 잘리지 않는다.
- [ ] 호버·편집·필터 적용 전후에도 의도하지 않은 위치 이동이나 포커스 손실이 없다.
- [ ] 관련 일정·완료·정렬·저장 규칙과 기존 데이터가 유지된다.

정보를 빨리 찾을 수 있는지, 그 자리에서 쉽게 추가·수정할 수 있는지, 정보량이 달라져도 정돈된 상태가 유지되는지를 함께 확인한 뒤 작업을 마칩니다.


## 목록 UX 보완 (2026-10-26, 이전 목록 배치보다 우선)
- 모든 리스트 헤더는 중앙 정렬합니다. 프로젝트명·업무명·할 일 본문은 왼쪽, 상태·날짜·동작은 중앙 정렬합니다.
- 오늘 할 일과 남은 할 일은 각각 독립적인 헤더 필터·검색·정렬을 제공합니다. 필터 결과가 없어도 해제 경로를 유지합니다.
- 헤더 드롭다운 아이콘은 호버·키보드 포커스·열린 상태에서만 보입니다. 터치에서는 표시하며, 나타날 때 글자가 밀리지 않도록 자리를 유지합니다.
- 프로젝트 열: 현황 | 프로젝트명 | 진행중인 업무 | 마감일 | 사업 종료일. 별도 이동 화살표는 없습니다. 업무가 여러 개면 업무별 행과 마감일을 대응시키고 프로젝트 공통 셀을 묶습니다. 마감일은 업무 due이며 할 일 마감·사업 종료일로 대체하지 않습니다.
- 프로젝트 상세는 하나의 표에서 업무 행 아래에 들여쓴 할 일 행을 배치합니다. 업무별 추가, 이름 검색, 마감 필터, 계층을 유지하는 정렬, 완료·취소 조회를 제공합니다.
- 리스트 집중 버튼의 보이는 외곽은 체크박스와 같은 18px, 내부 재생 아이콘은 10px입니다. 클릭 영역은 32px 이상을 유지합니다.

- 모든 표 형식 리스트에 기존 가로선과 같은 1px 세로 구분선을 표시합니다. 현황 헤더·본문은 중앙 정렬하며 작은 점과 은은한 배지로 진행중(청색)·완료(녹색)·보류(황색)·취소(적색)를 구별합니다. 기존 상태 값은 유지합니다.


- 프로젝트 상세는 속성 편집과 업무·할 일 표를 한 화면에서 제공합니다. 프로젝트 정보의 별도 상세 패널은 열지 않습니다. 기존 날짜·태그·인원·단계 편집기와 저장 로직을 재사용합니다.
- 프로젝트 현황 배지를 누르면 목록에서 현황을 변경합니다. 미완료 할 일이 있을 때 상태만 변경할지 오늘 배치도 해제할지 기존 규칙을 적용합니다. 현황 헤더의 필터 점은 표시하지 않습니다.
- 목록 빈값은 11px의 짧은 `-`로 표시합니다. 남은 할 일 제목은 13px, 개수는 12px입니다. 오늘 하기 동작은 16px 달력 아이콘과 툴팁으로 표시합니다.

- 오늘 할 일·남은 할 일·프로젝트·프로젝트 상세 표는 스크롤 영역 상단에 헤더를 고정합니다. 일반 표는 화면 높이의 60%(최대 560px)부터 내부 스크롤하며, 프로젝트 목록은 기존 가용 높이를 유지합니다. 가로 스크롤에도 헤더와 본문 열 너비가 일치하고 병합 셀의 구분선도 유지합니다.
