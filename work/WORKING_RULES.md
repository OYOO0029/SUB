# 업무 화면 작업 규칙

이 문서는 작업 절차와 데이터 보호 원칙만 정의합니다. 화면 규격의 유일한 기준은 [DESIGN.md](DESIGN.md)입니다. 과거 문서는 [이력](docs/history/)이며 구현 기준으로 읽지 않습니다.

## 우선순위와 변경
1. 현재 사용자의 명시적 요청 → DESIGN.md의 현재 규격 → 기존 공통 구현 순서로 적용합니다.
2. 새 요청이 기준을 변경하면 해당 항목을 교체합니다. 같은 문서 뒤에 ‘최신 기준’을 덧붙이지 않습니다.
3. 사용자 확정 요구와 에이전트 구현 선택을 구분합니다. 수치가 없는 요청은 기존 역할별 값을 재사용합니다. 새 값이 필요하면 이유와 적용 범위를 기록합니다.
4. 탐색·목록·상세의 같은 역할에는 같은 컴포넌트를 적용합니다. 수정 범위가 특정 화면이어도 공통 부품의 영향을 받는 연결 화면을 검사합니다.
5. 시안도 확정된 규격을 사용합니다. 비교할 변수만 바꾸고 데이터 의미·조작법·디자인을 한꺼번에 임의 변경하지 않습니다.

## 구현 책임
- 크기·색·여백은 common-ux.css의 토큰과 컴포넌트 규칙에 정의합니다. 동일 선택자에 후속 덮어쓰기를 쌓지 않습니다. 반응형 예외는 같은 파일의 미디어 규칙에서 관리합니다.
- 아이콘·버튼은 ui-components.js, 선택 메뉴는 choiceSelect/installSelectControls, 메뉴 상호작용은 surface-interactions.js를 사용합니다. 네이티브 select는 값 전달용으로 유지하고 사용자에게는 공통 메뉴를 표시합니다.
- 날짜는 date-picker.js, 상태 필터는 status-filter.js, 행 추가는 task-composer.js, 열 조절은 table-resize.js를 재사용합니다. 새 화면에 별도 복제품을 만들지 않습니다.
- 긴 텍스트, 빈 값, 필터 없음/결과 없음, 호버, 키보드, 터치를 설계에 포함합니다. 기능을 숨겨 미니멀하게 만드는 대신 진입점을 유지합니다.
- 정상 자동 저장 안내는 반복하지 않습니다. 저장 실패는 입력과 데이터를 보존하고 오류·재시도 경로를 표시합니다.

## 데이터 불변 조건
- 프로젝트 → 업무 → 할 일 관계와 하위 할 일(checks)을 구분합니다. 화면 정리로 레코드나 관계를 변환하지 않습니다.
- 작업 시작(startDate), 실제 마감(due/dueTime), 시간 배치(blocks), 기존 계획(plans), 리마인드는 독립 정보입니다. 하나를 바꿀 때 다른 값을 조용히 변경하지 않습니다.
- 기존 plans 기반 항목은 기존 해석을 유지합니다. 사용자가 시작일을 수정할 때만 선택적 startDate를 기록합니다. 일괄 마이그레이션하지 않습니다.
- 프로젝트 변경은 기존 updateItem의 연결 규칙을 사용합니다. 다른 프로젝트로 이동하면 맞지 않는 업무 연결만 해제하고 메모·일정·하위 할 일은 보존합니다.
- 삭제는 휴지통·되돌리기를 사용합니다. 프로젝트 삭제가 연결된 업무·할 일을 자동 삭제하지 않습니다. 사용자 정의 상태·단계와 과거 이미지 첨부 데이터도 보존합니다.
- 리마인드는 명시적 설정에만 동작합니다. 조회·알림 확인이 날짜나 완료 상태를 바꾸지 않습니다. 기간 양끝 포함, 종료일 없으면 계속 유효합니다.
- 계정별 저장·동기화 경로와 개인 데이터는 UX 변경으로 수정하지 않습니다. 실제 사용자 데이터 대신 분리된 로컬 fixture에서 검수합니다.

## 필수 작업 순서
1. 변경 목적과 적용 범위를 파악하고 DESIGN.md의 해당 규격을 확인합니다.
2. 공통 컴포넌트 수정인지 화면 전용 수정인지 결정하고 영향을 받는 화면을 나열합니다.
3. 기존 부품과 토큰을 수정합니다. 중복 정의·죽은 진입점·기본 브라우저 UI 노출을 점검합니다.
4. 관련 기능 검사와 실제 브라우저 화면 검수를 각각 수행합니다.
5. 규격·컴포넌트·검수 결과를 같은 변경에 포함합니다. 테스트 통과를 시각 검수 완료로 대신하지 않습니다.
6. 배포 요청이 있으면 빌드 성공과 공개 파일 버전을 확인합니다. 완료 보고에 확인 범위와 미확인 사항을 구분합니다.

## 공통 UX 변경 검수표
- 오늘 목록 / 남은 할 일 / 타임라인 / 프로젝트 목록 / 프로젝트 상세 / 업무 상세 / 할 일 상세 / 캘린더.
- 같은 기능의 글자·아이콘·클릭 영역·모서리·여백을 비교하고 텍스트 자체의 헤더 중앙 정렬을 측정합니다.
- 선택 메뉴의 기본·열림·선택·Escape·바깥 클릭과 키보드 포커스 복귀를 확인합니다.
- 빈 목록, 긴 제목, 다수 항목, 필터로 숨겨진 항목, 스크롤·열 조절을 확인합니다.
- 1280px 및 390/320px에서 페이지 넘침·패널 잘림·표 내부 스크롤을 확인합니다. 호버 없는 환경에는 동작 진입점이 있어야 합니다.
- 날짜·관계·저장 변경은 기존 데이터 보존, 연속 입력, 실패 재시도, 새로고침을 검사합니다.
- 검수 근거는 tests/ux-review.md에 기록합니다. 확인하지 않은 항목은 미확인으로 적습니다.
