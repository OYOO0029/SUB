# 개인 일정과 업무 통합

기존 `/schedule.html` 개인 일정과 `/work/` 업무 화면을 상단 전환 버튼으로 연결합니다. 두 화면은 같은 Supabase 로그인과 계정을 사용합니다. 개인 일정의 데이터 형식과 저장 키는 유지합니다.

## 업무 데이터 가져오기

1. 기존 업무 미리보기에서 설정 → JSON 내보내기로 최신 백업을 받습니다.
2. 통합 업무 화면의 업무 백업 가져오기에서 파일을 선택합니다. 로그인 전에도 파일을 브라우저에 보관할 수 있습니다.
3. 개인 일정에 쓰던 계정으로 로그인하고, 표시된 계정을 확인한 후 ‘이 계정에 가져오기’를 누릅니다.
4. 완료 메시지를 확인합니다. 다른 기기에서는 같은 주소·계정으로 로그인합니다.

가져오기는 프로젝트·업무·할 일·확인사항·관련 인원·기간·시간 배치·수동 순서·휴지통 기록을 유지합니다. 미리보기의 개인 일정 샘플과 트래커는 가져오지 않습니다. 동일한 백업을 다시 가져와도 중복 생성하지 않으며, 같은 ID의 내용이 다르면 원본을 보존하고 중단합니다. 성공한 원본 백업도 해당 계정의 로컬 보관함에 남깁니다. 파일은 공개 저장소나 배포 파일에 포함하지 않습니다.

## 저장과 동기화

- 공용 `spending_state` 행 안의 `myWorkV1`만 업데이트합니다. `myWeekV1`, `mySpendingV1`, 기존 가계부 필드를 유지합니다.
- 최신 행을 읽고 `updated_at` 조건부 쓰기를 사용합니다. 다른 영역에서 먼저 저장하면 최신 행을 다시 읽어 재시도합니다.
- 업무 자체의 동시 수정은 충돌 상태로 남기고 선택 전까지 덮어쓰지 않습니다.
- 미전송 수정과 로컬 캐시는 계정별로 분리합니다. 로그아웃·계정 변경 시 열려 있는 편집기와 화면 데이터를 비웁니다.
- 빈 계정에 데모 데이터나 이전 사용자의 기록을 생성하지 않습니다.

`npm test`는 가상 저장소로 개인·업무·가계부 보존, 충돌, 오프라인 복구, 계정 분리, 중복 가져오기를 검증합니다. `node tests/schedule-preview.mjs`는 실제 서버에 연결하지 않는 로컬 브라우저 검증 환경입니다.

## 새 기능의 데이터 계약

- 서버 슬롯은 `myWorkV1`, 내부 스키마는 `schemaVersion:1`을 유지합니다. 개인·가계부 슬롯을 포함한 서버 행 전체를 초기값으로 교체하지 않습니다.
- `projects`, `works`, `tasks`는 ID로 연결합니다. 할 일의 프로젝트 표시·조회는 기존 `taskContext`를 사용합니다. 직접 `projectId`와 업무를 통한 프로젝트 관계를 각각 임의 해석하지 않습니다.
- `due`/`dueTime`은 실제 마감, `plans`는 계획 기간, `blocks`는 시간 배치입니다. 완료 상태와 `completedAt`, 확인사항 `checks`, 휴지통 `deletedAt`, 날짜별 `dailyOrder`의 의미를 보존합니다.
- 새 화면은 공통 모델·workflow·repository·계정/동기화 모듈을 사용합니다. 화면마다 별도 저장 키나 전체 상태 복사본을 만들지 않습니다. 타이머 상태는 기기별 로컬 상태이며 서버 업무 데이터와 별개입니다.
- 스키마 변경 시 버전별 이전 함수와 이전/이후 왕복·관계 보존 검사를 추가합니다. 관계가 잘못된 레코드를 조용히 삭제하거나 재연결하지 않습니다.

## 구조 점검 및 남은 개선

현재 ID 연결, 계정별 캐시, 스키마 검증, 조건부 서버 쓰기, 가져오기 중복 방지는 구현되어 있습니다. 동일 브라우저의 다른 탭이 미전송 메모 복구 기록을 지우는 경로는 공통 엔진에서 방어하며 회귀 검사를 추가했습니다.

확장 전에 우선할 작업:
1. 이미지 base64를 전체 업무 JSON과 분리하고, 보호 백업의 용량·보관·내보내기 정책을 마련합니다. 현재 이미지 한 장 제한은 전체 저장량을 보장하지 않습니다.
2. 분산된 수정 동작을 공통 명령 계층으로 모으고, 직접 프로젝트/업무 관계 불일치 및 프로젝트의 다음 할 일 참조 등 업무 규칙 진단을 보강합니다. 현재 유효성 검사가 모든 업무 관계를 보장하지는 않습니다.
3. 협업·대규모 데이터가 필요해지면 전체 스냅샷 대신 개별 레코드와 리비전 단위로 저장합니다. 현재 같은 업무 슬롯의 동시 편집은 자동 병합 대신 충돌을 보존합니다.

이번 감사에서는 운영 데이터 마이그레이션이나 삭제를 수행하지 않았습니다. 저장 엔진의 범위와 제한은 [동기화 문서](../README-sync-ko.md#저장-경로-감사--2026-10-26)를 참고합니다.
