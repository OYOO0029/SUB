# 개인 일정과 업무 통합

기존 `/schedule.html` 개인 일정과 `/work/` 업무 화면을 상단 전환 버튼으로 연결합니다. 두 화면은 같은 Supabase 로그인과 계정을 사용합니다. 개인 일정의 데이터 형식과 저장 키는 유지합니다.

## 업무 데이터 가져오기

1. 기존 업무 미리보기에서 설정 → JSON 내보내기로 최신 백업을 받습니다.
2. 통합 업무 화면의 업무 백업 가져오기에서 파일을 선택합니다. 로그인 전에도 파일을 브라우저에 보관할 수 있습니다.
3. 개인 일정에 쓰던 계정으로 로그인하고, 표시된 계정을 확인한 후 ‘이 계정에 가져오기’를 누릅니다.
4. 완료 메시지를 확인합니다. 다른 기기에서는 같은 주소·계정으로 로그인합니다.

가져오기는 프로젝트·업무·할 일·확인사항·관련 인원·기간·시간 배치·수동 순서·휴지통 기록을 유지합니다. 미리보기의 개인 일정 샘플과 트래커는 가져오지 않습니다. 동일한 백업을 다시 가져와도 중복 생성하지 않으며, 같은 ID의 내용이 다르면 원본을 보존하고 중단합니다. 성공한 원본 백업도 해당 계정의 로컬 보관함에 남깁니다. 파일은 공개 저장소나 배포 파일에 포함하지 않습니다.

## 저장과 동기화

- 공용 `spending_state` 행 안의 `myWorkV1`만 업데이트합니다. `myWeekV1`, `mySpendingV1`, 기존 가계부 필드를 유지합니다.
- 최신 행을 읽고 `updated_at` 조건부 쓰기를 사용합니다. 다른 영역에서 먼저 저장하면 최신 행을 다시 읽어 재시도합니다.
- 업무 자체의 동시 수정은 충돌 상태로 남기고 선택 전까지 덮어쓰지 않습니다.
- 미전송 수정과 로컬 캐시는 계정별로 분리합니다. 로그아웃·계정 변경 시 열려 있는 편집기와 화면 데이터를 비웁니다.
- 빈 계정에 데모 데이터나 이전 사용자의 기록을 생성하지 않습니다.

`npm test`는 가상 저장소로 개인·업무·가계부 보존, 충돌, 오프라인 복구, 계정 분리, 중복 가져오기를 검증합니다. `node tests/schedule-preview.mjs`는 실제 서버에 연결하지 않는 로컬 브라우저 검증 환경입니다.
